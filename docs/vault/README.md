# プロジェクト管理の使い方

この Vault では、プロジェクト・タスク・メンバーの作業時間を Obsidian のノートで管理しています。
「Project Manager」プラグインが、**進み具合・遅れ・メンバーの忙しさ** を画面に表示します。

> [!tip] 困ったら
> 左のリボン（縦に並んだボタン）の **かばんのボタン**（プロジェクト管理）を押すと、主な操作がすべて出ます。
> キーボードなら `Ctrl + P` で「Project Manager」と打つと、コマンドの一覧が出ます。

---

## 1. まず知っておくこと

- **1件 = 1ノート** です
  - プロジェクト、エピック（作業のまとまり）、タスク、メンバー、作業ログが、それぞれ1つのノートです
- **ファイル名は ID**（`TASK-019a…` のような文字）です。ファイル名は変えないでください
  - 探すときはタイトルで探せます（`Ctrl + O` でタイトルを打つ）
- タイトルや所属などの情報は、ノートの上にある **プロパティ** に入っています
- **ノートは直接書き換えないでください**
  - 入力や変更は、プラグインの画面（フォーム・編集画面・カンバン）から行います
  - 画面からなら書き方の誤りが起きず、変えたところだけがノートに書き込まれます（5章）
  - ノートは中身を見るために開いてかまいません
- 進み具合や負荷などの計算結果はノートに書かれません。画面を開くたびに計算します

### ノートの種類

| 種類 | 中身 | 例 |
| --- | --- | --- |
| プロジェクト | 案件そのもの。期間・責任者・マイルストーン・工数配分 | 新製品プロモーションCG |
| エピック | プロジェクトの中の工程・まとまり | 設計、モデリング |
| タスク | 1人〜数人でする具体的な作業。担当者・期限日・見積 | 主要キャラのモデリング |
| メンバー | 1人1ノート。1日の通常の稼働時間、負荷許容率、個人休日 | 山田 太郎 |
| 作業ログ | メンバー×月ごとの予定・実績の時間の記録 | 山田 太郎の 2026年11月 |

## 2. 毎日の使い方

### 2.1 作業ログを付ける（予定・実績の時間）

1. かばんのボタン →「**作業ログを入力**」
2. メンバー・日付・プロジェクト・タスクを選び、**予定（h）** と **実績（h）** を入れて保存
   - 時間は **0.25 刻み**（15分単位）です。例：1.5
   - その日・そのタスクの行がすでにあれば、書き換えになります（枠の色と文で分かります）
   - その月の作業ログのノートが無ければ、自動で作られます
3. 記録を消す・まとめて直すときは、同じ画面の「**（月）の記録を一覧で編集**」を押す
   - その月の記録が表で開き、日付・タスク・予定・実績・メモを変える、行を足す・消すことができます
   - タスクの欄を押すと、タスク名（かプロジェクト名）で探して選ぶ画面が開きます
   - 日付はその月の中だけです。ほかの月の記録は、行を消して「作業ログを入力」で入れ直します

**タスクから入れる**：**プロジェクト状況** でエピックの ▶ を押してタスクを開き、タスクの行の「**＋工数**」を押します。

- そのタスクを選んだ状態で同じ画面が開きます（プロジェクトとタスクを選ぶ手間が省けます）
- メンバーは、前回選んだ人がそのタスクの担当者ならその人、担当者が1人ならその人が選ばれます
- 「続けて入力」のあともタスクはそのままなので、日付を変えて続けて入れられます

> [!note] 予定と実績
> - **予定**：その日にその作業に使うつもりの時間。メンバーの「負荷率」の計算に使います
> - **実績**：実際に使った時間。「工数超過」（見積より多く使った）の判定に使います

### 2.2 タスクの進み具合を変える

どれかの方法で、タスクの **ステータス** を変えます。

- **カンバン** でカードを別の列へドラッグする（いちばん簡単）
- 各画面のタスクの行やカードの「**フォーム**」を押す（入力補助フォーム。選ぶだけで入力できます）
- タスクのノートを開いた状態で、かばんのボタン →「**開いているタスクを編集**」（同じフォーム）

タスクの細かい作業は **チェックリスト** にします。

- 開き方：タスクのフォームの「**チェックリストを編集**」
  - タスク一覧・WBS・プロジェクト状況の「進捗」の値（例：33%（1/3））を押しても開けます
  - タスクのノートを右クリック →「チェックリストを編集」でも開けます
- 項目を足す・チェックする・消すことができます。入力欄で Enter を押すと、次の項目を足せます
- チェックした割合が、各画面の「進捗」に出ます（タスクが完了のステータスなら「完了」）
- 新しい項目は、今ある項目の下に足されます。並べ替えはできません

一覧の日付が休日のときは、日付の後ろに休日の種類の印が付きます（マウスを乗せると理由が出ます）。

| 印 | 色 | 意味 |
| --- | --- | --- |
| 社休 | 橙 | 会社休日（設定の会社カレンダーの休日） |
| 個休 | 紫 | その行の人の個人休日（2.3）。タスクは担当者のだれか、エピックは担当者、プロジェクトは責任者 |
| 土日 | 灰 | 土曜・日曜（土日を休日にする設定のとき） |

- 会社休日・土日に開始日を置くと、次の稼働日から始まる計算になります
- 個人休日は印が付くだけで、計算は変わりません

### 2.3 個人休日（有給など）を入れる

**メンバー状況** の上の「**個人休日を編集**」から自分を選ぶと、休みの日を足す・変える・消すことができます。

- メンバーのノートを右クリック →「個人休日を編集」でも開けます
- 日付を選び、メモ（有給など）は空でもかまいません
- 変えた行だけが、メンバーのノートの「個人休日」の表に書き込まれます
- 一覧の日付に「個休」の印が付きます（メンバー状況には付きません）
- **負荷率や日程の計算には使いません**（休みの日に作業ログが入っていても警告にはなりません）

### 2.4 ノートを作る

かばんのボタン →「新しいプロジェクト」「新しいエピック」「新しいタスク」「新しいメンバー」。

- ID や必要なプロパティは自動で入ります
- まだ決まっていないプロパティ（開始日・担当者など）も、空の欄としてはじめから並びます
- 各画面の上の「新しいタスク」などのボタンからも作れます（絞り込んでいるプロジェクトが選ばれます）
- 作ってもノートは開かず、画面の右上に「作成しました」と出ます。作ったものは各画面にすぐ出ます

作ったあとの入力：

| 何を | どこから |
| --- | --- |
| エピックの担当者・開始日・完了予定日・インプット・アウトプットなど | **プロジェクト状況** のエピックの行の「**フォーム**」（WBS・ガントチャートにもあります） |
| メンバーの氏名・1日の通常稼働時間・負荷許容率・在籍 | **メンバー状況** のメンバー名の横の「**フォーム**」 |
| プロジェクトの名前・案件ID・ステータス・期間・責任者 | **プロジェクト状況** の上の「**フォームで編集**」 |
| マイルストーン・工数配分 | **プロジェクト状況** のそれぞれの見出しの横の「**編集**」 |

- メンバー・プロジェクトのフォームは、ノートを右クリック →「入力補助フォームで編集」でも開けます
- エピックのプロジェクトは、タスクやマイルストーンの連動が無いときだけ変えられます（作り間違えの直し用）
- マイルストーンは、行を変える・足す・消す画面です
- 工数配分は、縦にメンバー・横に月のマス目に配分(h)を入れる画面です
  - プロジェクトの期間の月と、配分か作業ログのあるメンバー・責任者が最初から並びます
  - 下の「＋メンバー」「＋月」で足せます。マスを空にするとその配分を消します
  - マスの下には、その月・メンバーの予定・実績（作業ログの合計）が参考に出ます
  - 予定が配分を超えると赤になります
- どの画面も、変えたところだけがノートに書き換わります

## 3. 画面（ビュー）の一覧

どれも、かばんのボタンから開けます。どの画面も上の部分は同じ並びです。

1. 画面の名前と一行の説明（右に件数）
2. **絞り込み**（プロジェクト・担当者・ステータスなど。タブを閉じるまで覚えています）
3. 左に **表示の設定**（単位・グループ・「罫線を表示」など）、右に **操作のボタン**（新しいタスクなど）
4. 色や印の意味（凡例）と注意

| 画面 | 何が分かるか |
| --- | --- |
| **ダッシュボード** | 全プロジェクトの進捗・工数・警告、工数のグラフ、メンバーの負荷率、2週間以内のマイルストーン |
| **タスク一覧** | タスクを表で一覧。並べ替え・グループ分け |
| **カンバン** | ステータスごとの列にタスクのカード |
| **WBS** | プロジェクト → エピック → タスクの階層と、計算上の日程 |
| **ガントチャート** | 日程の棒グラフ。期限日・マイルストーン・今日の線 |
| **メンバー状況** | メンバーごとの負荷率（全プロジェクトの合計） |
| **プロジェクト状況** | 1つのプロジェクトの概要・マイルストーン・エピック・工数配分 |
| **警告一覧** | ノートの書き方の誤り、ファイル名が ID の形でないファイル |

### ダッシュボード

- 行をクリックすると各画面へ
- 工数のグラフ：選んだプロジェクトの「工数の累積」と「進捗率」。チェックで出し入れできます
- メンバーの負荷率の横棒グラフ（在籍者全員）
  - 縦の線が100%、黒い印がその人の負荷許容率。緑＝100%以下、橙＝負荷注意、赤＝負荷警告
  - 期間は「今週・来週・今月・来月」、並び順は「名前順・負荷率の高い順・低い順」から選ぶ
  - メンバー名はメンバーのノート、棒はメンバー状況を開く
- グラフにマウスを乗せると値が出ます（負荷率の棒は予定の時間と働ける時間）
- HTMLレポートの書き出し（6章）

### タスク一覧・カンバン

- タスク一覧：行をクリックでノートを開く（フォームで開くにも切り替えられます）
- カンバン：カードを列へドラッグでステータスを変える
  - 「列の幅」のつまみ・「画面の幅に合わせる」で列の幅を変える

### WBS・ガントチャート

- 行の先頭の ▶／▼ を押して開け閉め（プロジェクト状況も同じ）
- ガントの棒の色は種類ごとの色（7章）。単位が「日」のときは休日の列がグレー
- ガントで棒にマウスを乗せると依存関係の線。単位（日・週・月）を切り替えられます
- 依存関係のあるタスクには ⇆ の印。「依存の印を表示」で出し入れできます
- エピック・タスクの行の「フォーム」で入力補助フォームを開く
- プロジェクトの行の「＋エピック」でエピックを、エピックの行の「＋タスク」でタスクを作る
- タスクにも WBS 番号が付きます（例：エピックが 1.2 なら 1.2.1、1.2.2…）。新しいタスクには続きの番号
- エピック・タスクの行をドラッグすると、順番と番号を入れ替えられます（プロジェクト状況でも同じ）
  - ガントでは左の名前の欄をつかんでドラッグします
  - 落とした行の上半分なら前、下半分なら後ろに入ります（青い線が出ます）
  - エピックは同じプロジェクトの中、タスクは同じエピックの中だけで動かせます
  - タスクの番号は、タスクの「フォーム」の「WBS番号」でも直せます

### メンバー状況

- マスをクリックでプロジェクト別の内訳
- メンバー名をクリックでメンバーのノート、「フォーム」でメンバーの情報を変える
- 「個人休日を編集」で休みの日を入力（2.3）

### プロジェクト状況

- エピックの行の ▶／▼ を押してタスクを開け閉め
- タスクは WBS 番号順。エピック・タスクの行をドラッグすると番号を入れ替えられます（WBS と同じ）
- エピックの行の「フォーム」で担当者・開始日・完了予定日を入力
- タスクの行の「＋工数」でそのタスクの作業ログを入力（2.1）
- 上の「フォームで編集」でプロジェクトのプロパティ、マイルストーン・工数配分の「編集」で表を変える

### 警告一覧

- 行をクリックで、直す画面（入力補助フォーム、表の編集画面）を開く
- 行の右の「ノート」でノートも開けます
- 直す画面が無いもの（プロパティが読めないほど崩れたものなど）は、クリックでノートを開く

> [!tip] 色の意味（日程）
> - **赤**：期限日より後に終わりそう、または期限日を過ぎている
> - **橙**：遅れを反映して日程をずらしている
> - **薄い色**：完了・停止したもの

## 4. 言葉の意味

| 言葉 | 意味 |
| --- | --- |
| 進捗率 | 完了したタスクの数 ÷ タスクの数。保留・中止のタスクは数えません |
| 見積・予定・実績 | 見積＝タスク全体でかかる見込みの時間。予定・実績＝作業ログの合計 |
| 進捗率のグラフ | 青い線は、その日までに終わるはずのタスクの割合（予定）。橙の点は、今日の実際の進捗率。点が線より下なら遅れ。過去の実際の進捗率は記録しないので、点は今日の分だけ |
| 工数の累積のグラフ | 予定と実績の時間を日ごとに積み上げた線。実績の線が予定より下なら、予定ほど作業が進んでいない（か、時間をかけずに済んでいる）。予定の線が見積の線を超えそうなら、見積が足りない |
| 負荷率 | 予定の時間 ÷ 働ける時間（稼働日 × 1日の通常稼働時間）。100% を超えると「負荷注意」、負荷許容率を超えると「負荷警告」 |
| 稼働日 | 会社カレンダーの休日（土日・祝日など）以外の日。個人休日は稼働日のまま数えます（印だけ。2.3） |
| 先行タスク | そのタスクより先に終わらせる必要のあるタスク。先行が遅れると、後のタスクの計算上の日程もずれます |
| 計算上の日程 | 先行タスク・所要日数・遅れから計算した開始日・終了日。ノートには書かれません |
| マイルストーン | プロジェクトの節目の日（中間レビュー、納品など）。プロジェクト状況のマイルストーンの「編集」から入れます |
| クローズ | プロジェクトのステータスを「クローズ」にすると、終わったプロジェクトとして普段の画面から外れます |

### 警告の種類

警告は種類ごとの小さな印（［期限超過 1］など）で出ます。色は種類の目安で、名前が書いてあります。

- ダッシュボード・プロジェクト状況・WBS の警告の印をクリックすると、警告の出ているタスクだけをタスク一覧で開けます
- 配分超過は、プロジェクト状況の工数配分の表で確かめます

| 警告 | 出る条件 | 直し方の例 |
| --- | --- | --- |
| 期限超過 | 期限日を過ぎたのに完了していない | 終わっていれば完了に。終わっていなければ期限日を相談して変える |
| 期限超過見込み | 先行の遅れなどで、計算上の終了日が期限日より後 | 先行タスクを急ぐ、所要日数・期限日を見直す |
| 工数超過 | 実績の合計が見積を超えた | 見積を見直す |
| 配分超過 | プロジェクトのある月・ある人の予定が、工数配分を超えた | 予定を減らすか、配分を見直す |
| 負荷注意・負荷警告 | メンバーの予定が多すぎる | 予定を別の人・別の日に移す |
| 休日稼働 | 休日に予定・実績が入っている（メンバー状況のセルに「休稼」の印） | 意図したものか確かめる |

## 5. SVN で使うときの約束

この Vault は SVN で全員と共有しています。ぶつかり（コンフリクト）を防ぐため、次を守ってください。

1. **作業を始める前に「SVN 更新」**、終わったら **「SVN コミット」**（TortoiseSVN の右クリックメニュー）
2. **同じタスクを複数人で同時に編集しない**
3. ノートを **エクスプローラーで移動・名前変更しない**（履歴が途切れます）。移動は TortoiseSVN の「移動」で
4. **ノートは直接書き換えず、プラグインの画面から変える**（1章）
   - 作業ログ：「作業ログを入力」かタスクの行の「＋工数」（まとめて直すときは「記録を一覧で編集」）
   - タスク・エピック・プロジェクト・メンバー：「フォーム」
   - マイルストーン・工数配分：プロジェクト状況の「編集」
   - 個人休日：「個人休日を編集」。チェックリスト：「チェックリストを編集」
   - ノートの表を手で編集すると、Obsidian が表全体の空白を整え直し、全部の行が変わったことになります
   - ほかの人の変更とぶつかりやすくなります

## 6. ときどき使う機能

### HTMLレポート（上司などへの共有）

SVN を使わない人にも状況を見てもらうための、ブラウザで開ける1つのファイルです。

1. 出力先を決める（最初の1回だけ）
   - 設定 → Project Manager →「このパソコンだけの設定」→「HTMLレポート」の「**出力先**」
   - 共有フォルダ（例：`\\server\share\pm-report`）を入れる
2. かばんのボタン（またはダッシュボードのボタン）→「**HTMLレポートを書き出す**」
3. 出力先の `project-report.html` を開く。クローズしていない全プロジェクトの状況が入っています

### アーカイブ（終わったプロジェクトの片付け）

1. プロジェクトのステータスを「クローズ」にする
2. かばんのボタン →「**アーカイブ対象の一覧**」で、動かすファイルと移動先を確かめる
3. 画面の手順に従い、**TortoiseSVN の「移動」** でアーカイブフォルダへ動かしてコミットする
   - プラグインはファイルを動かしません

### 画面がおかしいとき

- 画面の数字が古い気がする：リボンの **↻ のボタン**（データを再読み込み）
- 警告一覧に誤りが出ている：行をクリックして開いた画面で直して保存する
  - 画面が無いものはノートが開くので、書かれている内容を直す
- 警告一覧に「ファイル名が ID の形でない」と出ている：作りかけや、コピーでできたファイルです
  - 不要なら TortoiseSVN の「削除」で消してコミットする
  - 必要な内容なら、プラグインの作成コマンドで作り直して中身を移す
- それでも直らない：`Ctrl + Shift + I` → 「Console」に出る赤い文を、管理者に送ってください

## 7. 個人の設定

設定 → Project Manager の「**このパソコンだけの設定**」。見出し（▶／▼）を押すと開け閉めできます。

| グループ | 設定 | 内容 |
| --- | --- | --- |
| 表示 | プロジェクトの表示名 | 画面でプロジェクトを、簡易名・案件ID・正式名のどれで表示するか |
| 表示 | ノートを開く場所 | 右枠（初期値）／新しいタブ／別ウィンドウ。ノートを作ったときは開きません |
| 表示 | 左枠（ビュー）の幅 | 左右に分けたときの左枠の幅（30〜80%、初期値60%） |
| HTMLレポート | 出力先 | 6章を参照 |

- 右枠：画面の右半分にノートを開き、ダッシュボードなどの画面は左半分に開きます
  - クリックすると右半分のノートが切り替わり、中ボタンか Ctrl＋クリックなら新しいタブに開きます
- 左枠の幅は、左右に分けたときと、ここを動かしたときに当てはまります
  - マウスで境目を動かした幅はそのままです

「**全員共通の設定**」（ステータス・会社カレンダー・種類ごとの色・フォルダ）は **全員に影響します**。
変えるときは管理者に相談してください。

- 種類ごとの色：プロジェクト・エピック・タスクの色
  - ガントチャートの棒と、各画面のタイトルの前の小さな丸（●）に使います
  - ガントの棒は、遅れ（橙）・期限より後（赤）・完了（グレー）のときはその色が優先されます
- ステータスごとの色：ステータスの行の色を選ぶ欄で決めます
  - 各画面の表と HTMLレポートで、ステータスがその色の枠で囲まれます
  - 選んでいないステータスは分類ごとの色（未着手系＝灰、進行中系＝青、完了系＝緑、停止系＝橙）
  - ↺ のボタンで分類の色に戻せます
